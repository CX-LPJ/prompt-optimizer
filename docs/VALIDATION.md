## 手动复查

供应商 UI 检查不需要真实 API 密钥：先将主程序构建到 `provider-update/PromptOptimizer.exe`；使用 .NET Framework 编译器，将 `tests/ProviderUiSmoke.cs` 编译到同目录的 `ProviderUiSmoke.exe`，引用该主程序、System.Windows.Forms.dll 和 System.Drawing.dll；然后运行 `node tests/provider-ui-smoke.cjs`。它创建独立测试配置、本机 HTTP 服务和设置窗口，不修改实际供应商配置。已有 Codex 登录的安装实例还可运行 `tests/provider-codex-smoke.ps1 -ToolDirectory <工具绝对路径>`，这会发起一次真实模型连接测试。

UI 测试会启动模型并使用额度，只对测试材料运行。先构建 `tests/EditorFixture.cs` 为同目录的 `EditorFixture.exe`。`external-smoke.ps1` 使用独立窗口、`external-translation-test.txt` 和本地 `web-editor.html`；浏览器测试默认寻找标准安装路径的 Edge。

`translation-smoke.ps1` 只应对空白 Codex 草稿框运行。`hotkey-smoke.ps1` 按默认键位测试；已经改键的环境应先检查脚本使用的键位。检查结束后应恢复测试文本并关闭测试窗口。
